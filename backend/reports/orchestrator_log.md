.npy data was synthetic (`splits.json` had `"ci_synthetic": true` flag, all
mtimes identical, landmark 9 not at canonical (0, 1, 0)). Investigation
showed:

- The `lsc-pipeline-engineer` agent (or its `full_pipeline.bat`) re-ran the
  LEGACY `prepare_sequences_from_lsc50.py` against the FULL LSC50 vocabulary
  (33+ words, not just the 12 active). This wrote 1194 entries to
  `data/sequences/manifest.json` referencing words like `apoyar`,
  `buenas_noches`, `tres`, `uno` that aren't in the 12-class vocabulary.
- The actual filesystem ended up with 1002 .npy files in the 12 active
  word directories, but the files were a mix of (a) the previous
  rotation-invariant extraction and (b) the new legacy extraction —
  **two different normalization spaces**.
- The `lsc-baseline-trainer` also accidentally overwrote
  `models/sequence/sign_gru.pth` because `train_sequence.py` has no
  `--model-save-path` flag.

### Lessons learned

- **Sub-agents should never re-run an extractor that has destructive side
  effects** (like overwriting the manifest with a different vocabulary)
  without first verifying the input data is in the expected state.
- **Always check filesystem invariants before training.** The 1002 files vs
  510 expected files discrepancy was the early warning sign.
- **The orchestrator must verify sub-agent output, not just trust the
  summary.** The baseline-trainer flagged the data anomaly, but the
  pipeline-engineer had already corrupted the data by the time the
  orchestrator was reviewing reports.
- **The next iteration of `lsc-pipeline-engineer` should add a data-integrity
  check** at the start of `full_pipeline.bat` that asserts the
  `splits.json` doesn't have the `ci_synthetic` flag and that the file
  count matches the expected manifest.

### What did NOT meet the user's target
- ≥90% top-1 without calibration: **NOT ACHIEVED**. Best honest
  result is 84.01% (GRU). The 12-class LSC50 dataset is too small
  (26-55 samples per class, 18 signers) for the model to fully
  generalize. To reach 90%, the user would need either:
  1. A larger dataset (more signers per word, e.g., 50+ per class).
  2. Real user data collected via the on-device calibration flow

     but hasn't been tested with real users.
